## What "complete" means here

decoder: accept + size reject + spec alignment (accept_spec_k, reject_size_spec, reject_complete) + Desc codec equality / correspondence + accept witness + reject witness, all kernel-checked theorems with standard axioms; accept / reject / spec_k / reject_size_spec theorems keyed to the function by the code constant in their type (the function is the subject: no other target code constant of the theorem calls it); witnesses and spec theorems use the mapped accept / reject theorem.

It does NOT include:

- morestack paths (the `jbe` to `runtime.morestack_noctxt` at entry)
- `runtime.writeBarrier` != 0 (every accept theorem assumes the flag word is 0)
- runtime callee bodies (makeslice / memmove / growslice / newobject / fmt.errorf: contract hypotheses, MakesliceC / MemmoveC / ...)
- callee error returns (the `fmt.Errorf` wrap paths of delegated fields; `reject_complete` covers the size path condition only)
- growslice (encoder capacity growth beyond the listed theorems; FINDINGS.md: "Growslice contract gives no lower bound on the remaining heap")
- x86-64 hardware execution (semantics = Kraken's model of the amd64 instructions; no hardware run)

## What this table cannot detect

- a row whose `codec` or `reject_complete` names ANOTHER type's theorem: these two parts are checked for existence, kind and axioms only (their types hold no code constant, their proofs use no mapped theorem; found by an earlier review). Keying them to the row's Desc constant needs a new column in `inventory_decls.lean`; not done
- that a theorem's statement says what its part name means (accept, reject, spec): the mapping chooses names by their form (SPEC.md); the statements are checked by review and by the kinds, not by this script
- a theorem with two target code constants of which neither calls the other (it fails: no single subject)
- that <decls.tsv> was made on the built tree of the same commit (its header has the Lean version, no commit id)
- that an encoder row's premise text and NOT-proved text say what the mapped reject / growslice theorems assume (hand-written per row; checked by review against the theorem statements, not by this script)
- methods outside `github.com/OffchainLabs/prysm/v7/` (e.g. `github.com/holiman/uint256`) and SSZ methods with names outside the listed kinds
