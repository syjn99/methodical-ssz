# X5: X4 생성기를 Go 1.26.10 Prysm 목록에 적용

**판정: 범위 안 132개 타입 중 46개가 size 정리 하나를 가진다(Lean 통과, 변이 잡힘, 공리 표준만, 링크 검사 PASS). 디코더·인코더 의무는 모든 타입에서 거부됐다. 모든 의무를 통과한 타입은 0개다. 게이트 1c 통과가 아니다.**
실험적 기준선(Go 1.26.10, `MANIFEST.md`)이다. Go 1.26.3 증명은 하나도 다시 쓰지 않는다. 코드 상수는 이 디렉터리의 `.S`를 include한다.
수는 모두 `x5.json`에서 프로그램이 센다(`gen/x5/x5run.py table`).

## 1. 무엇을 했나

1. 링크 표(`link/`): Go 1.26.10 ELF `c6403c02…911e`의 함수 136개(범위 안 132개 타입의 SizeSSZ, v1alpha1 Checkpoint·AttestationData의 디코더·인코더). `gen/x5/x5run.py link`가 전체 objdump에서 이 함수만 골랐다. `link/conv.py --norm`과 `link/check.py`를 고치지 않고 그대로 돌렸다.
   - `link/RESULT`: (a) 136, (b) 82, (c), (d) 5026개 명령어(4960 바이트 같음, 66 padding), (e), (f) 2 모두 PASS, `BUNDLE sha256 1bdfc4f0…aa5af`(logs/126).
   - (f)는 빈 데이터 디렉터리를 거부한다(logs/125). 그래서 `gen/x5/x5data.py`가 데이터 항목 둘을 같은 형식으로 썼다(Go 1.26.10 Checkpoint 디코더의 makeslice 원소 타입 단어, `ssz.ErrSize` 주소). 아직 이것을 읽는 X5 증명은 없다.
   - `check.py`는 fix3의 `lean/Fk/Code.lean`·`AXIOMS.txt` 해시도 RESULT에 적는다. 그것은 이 이름공간과 관계없다.
2. 타입마다 X4 생성기가 Desc로 고르는 틀을 Go 1.26.10 코드에 대 봤다(`x5run.py gen`). 손 수정은 없다.
   - size: 고정 크기이고 SizeSSZ가 `mov $n,%eax; retq`이면 X4 size 틀(문장은 Desc 고정 크기, 증명은 지시 걷기). 46개 생성.
   - 디코더·인코더: Desc 필드 종류로 틀을 고른다. 맞지 않으면 생성기 거부 이유를 적는다.
   - 고정 틀이 있는 Checkpoint·AttestationData는 고정 틀 검사를 끄고 손 글을 새 코드에 억지로 대서 Lean을 돌렸다(생성 방식이 아니다. Lean이 어디서 거부하는지 기록하려는 것). 4개 모두 Lean 오류.
3. Lean(logs/128, 129, gate + memcap 6 GiB, oom_kill 5→5): `Gen1cX4.X5.Code`, `Gen1cX4.X5.Size`(이름공간 `Gen1cX5`) 빌드 통과. 변이 46개(`mov $n+1,%eax`)가 모두 자기 정리 안에서 실패(`x5-sizemut-ranges.json`). 공리: 46개 이름 표준만.

## 2. 결과 (`x5.json`)

| 의무 | 생성 + 증명 | 거부 | 분류 |
| --- | --- | --- | --- |
| size | 46 | 86 | 자동화 한계 86(가변 크기 타입: SizeSSZ가 크기를 계산한다; 상수 크기 아닌 고정 타입 없음) |
| 디코더·인코더 | 0 | 134 | 계약 부재 2, 자동화 한계 132 |

- 계약 부재 2: v1alpha1 Checkpoint·AttestationData 디코더. Prysm 코드가 손 작성 원시 타입 메서드(`primitives.Epoch/Slot/CommitteeIndex.UnmarshalSSZ`)를 부른다. 그 메서드에는 함수 명세도 계약도 없다(사용자 결정 대기, INBOX 005 2항). 손 사례 코드는 이것을 인라인한다. 그래서 고정 틀이 맞지 않는다(108 대 72 지시).
- 억지로 댄 Lean 오류(첫 오류): Checkpoint 디코더 116줄 `ecancel`, 인코더 95줄 `ecancel`, AttestationData 디코더 177줄 `load_step` 통일 실패, 인코더 127줄 `rewrite` 실패.
- 자동화 한계 132: 리스트 필드가 다른 필드와 함께 있음 33(X4 리스트 틀은 리스트 필드 하나만), 바이트 벡터·컨테이너 등 필드에 틀 없음(고정 틀은 손 사례 두 타입뿐), uint만인 5개 타입은 Scalars 틀이 bool 하나를 요구하고 길이 거부 틀은 프레임 없는 잎 함수용이다.
- 새 명령어: 첫 거부가 틀 단계라서 Lean 단계까지 가지 않았다. P1의 `%riz` 13개 함수(Kraken 파서 빈틈)는 그 앞에 있다.
- 생성기(sszgen 698c202) 새 결함: X5에서 찾지 못했다. 실패는 모두 우리 생성기(gen/x4)의 틀 범위 문제다.

## 3. 게이트 1c 여섯 요소 (size 46개만)

| 요소 | 상태 |
| --- | --- |
| 1 문장 | Desc 고정 크기에서 생성. 비교할 손 정리가 없다(Prysm 타입) |
| 2 구체 Host 증인 | 하지 않았다 |
| 3 기계어 정리 | 46개 Lean 통과 |
| 4 링크 검사 | PASS (a)–(f), 번들 `1bdfc4f0…` |
| 5 부정 시험 | 46/46 변이가 지정 정리 안에서 실패, 대조군(라이브러리 모듈) 통과 |
| 6 Go 값 | 해당 없음(size는 메모리를 읽지 않는다). 검사하지 않았다 |

타입 하나의 고정 목록 의무(평균 약 28개, 전체 3676개) 중 size 하나만 증명됐다. 어떤 타입도 통과가 아니다.
