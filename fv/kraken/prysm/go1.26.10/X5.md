**Verdict at tag `archive/fv-before-workflow`: of 132 in-scope types, 46 had one size theorem (Lean passed, mutation caught, standard axioms only, link check PASS). The decoder and encoder obligations were rejected for all types. 0 types passed all obligations. This is not a gate 1c pass.**
On 2026-11-12, commit `84a4747` removed the X5 Lean modules (`Gen1cX4.X5.*`, in `lean/Gen1cX4`) and the scripts `gen/x5/`. Tag `archive/fv-before-workflow` holds them.

This is an experimental baseline (Go 1.26.10, `MANIFEST.md`). It rewrites none of the Go 1.26.3 proofs. The code constants include the `.S` of this directory.
A program counted all numbers from `x5.json` (`gen/x5/x5run.py table`, removed on 2026-11-12).

## 1. What was done

1. Link table (`link/`): 136 functions of the Go 1.26.10 ELF `c6403c02…911e` (SizeSSZ of the 132 in-scope types, and the decoders and encoders of v1alpha1 Checkpoint and AttestationData). `gen/x5/x5run.py link` selected only these functions from the full objdump. We ran `link/conv.py --norm` and `link/check.py` as they are, with no changes.
   - `link/RESULT`: (a) 136, (b) 82, (c), (d) 5026 instructions (4960 bytes equal, 66 padding), (e), (f) 2, all PASS, `BUNDLE sha256 1bdfc4f0…aa5af` (logs/126).
   - (f) rejects an empty data directory (logs/125). Thus `gen/x5/x5data.py` wrote two data items in the same format (the makeslice element type word of the Go 1.26.10 Checkpoint decoder, and the `ssz.ErrSize` address). No X5 proof read them.
   - `check.py` also wrote the hashes of the fix3 `lean/Fk/Code.lean` and `AXIOMS.txt` into RESULT. They have no relation to this namespace.
2. For each type, we tried the template that the X4 generator selects by Desc against the Go 1.26.10 code (`x5run.py gen`). There are no hand changes.
   - size: if the type has a fixed size and SizeSSZ is `mov $n,%eax; retq`, the X4 size template applies (statement is the Desc fixed size, proof is an instruction walk). 46 generated.
   - Decoder and encoder: the Desc field kinds select the template. If it does not match, the generator records the reject reason.
   - For Checkpoint and AttestationData, which have fixed templates, we disabled the fixed-template check, forced the hand text onto the new code and ran Lean. (This is not the generation method. The purpose is to record where Lean rejects.) All 4 gave Lean errors.
3. Lean (logs/128, 129, gate + memcap 6 GiB, oom_kill 5→5): `Gen1cX4.X5.Code` and `Gen1cX4.X5.Size` (namespace `Gen1cX5`) built and passed. All 46 mutations (`mov $n+1,%eax`) failed inside their own theorems (`x5-sizemut-ranges.json`). Axioms: standard only for the 46 names.
