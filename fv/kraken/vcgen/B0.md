# B0: vcgen 브랜치 평가

## 결론: main(6064eec)에 남는다

대상: sgraf812/kraken `vcgen` `a4cce2ec6d840376e4dbbf4a11a777ebdf42a3cb`, Lean `nightly-2026-10-29`, EthLib 8621856.
이 갈래는 main과 공통 조상 `e540187` 뒤로 갈라졌다. 의미론 파일이 다르고 정교화기 `include_x64`가 없다.

- 빌드: vcgen Kraken과 EthLib SSZ 폐포가 빌드된다(262 s, 1.78 GB).
- Go ABIInternal: 된다. `funspec`이 호출 규약 `GoABI := ⟨[.rsp, .r14], fun k => 8 * k⟩`를 받는다. X15는 따로 전제로 둔다.
- 명령어 명세: `Scalars.UnmarshalSSZ` 수용 경로(25개 명령어)에 `@[spec]` 5개가 빠졌다. `Vg/Specs.lean`에 증명했다.
- 검증 조건: 레이블 불변식 `ScInv`(`Vg/ScAccept.lean`)를 넣은 명세에서 VC 20개, `kfinish`로 닫힘 3개, 열림 17개(7.1 s).
  열린 것은 저장 뒤 적재의 `Option.isSome`(11)과 `Mem.WritesOnly` 합성이다.
  닫으려면 다른 메모리 모델(`Mem.Mapped`, `WritesOnly`, `loadInt`/`storeInt`)로 기존 분리 논리 정리 약 1000줄을 다시 써야 한다.
- 수치는 이 명세에 대한 측정이다. vcgen의 성능이나 한계로 읽지 않는다.
- 신뢰 기반: main에 합쳐지지 않은 갈래로 옮기면 의미론이 바뀐다.

`funspec … at s`의 `s`는 호출 전 상태다. 그래서 spill 칸은 호출 전 `rsp + 8`이다.

Kraken 요청: `@[spec]` 형태 추가(`movzx` 메모리 원천, 8비트 레지스터 비교, 메모리 즉치값 저장, 64비트 base+disp 적재). vcgen의 main 합류 일정.

`lake build`는 `Vg.Probe`, `Vg.Specs`만 빌드한다. `Vg/ScAccept.lean`은 열린 목표를 남긴다.
